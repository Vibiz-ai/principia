# Principia Cloud

Principia Cloud keeps your agents working while your Mac sleeps. Schedules fire, connectors answer, and every
company's Passport is served from one URL. You bring the Claude and ChatGPT (Codex) accounts you already pay for. The
desktop app stays the cockpit: it attaches to a cloud the way Git attaches to a remote. Design: [docs/CLOUD.md](../docs/CLOUD.md).

## Start a cloud

Pick one. Each ends with a **connect link** in the cloud's log, which you paste into Principia → **Cloud**.

### One button: Render (no tunnel, https included)

[Deploy to Render](https://render.com/deploy?repo=https://github.com/Vibiz-ai/principia) uses [`render.yaml`](../render.yaml):
one web service from the published image, with a disk. Render gives it an https address, which the cloud uses for your
connect link, your phone and your Open Passport (served on the same origin, so ChatGPT and Claude.ai connect to it with
no second domain). There is nothing to type: the master key is generated by Render and never written to the disk.

After the first deploy, open the service's **Logs** and copy the line `Connect link: https://….onrender.com/pair#XXXX-XXXX`.
A disk needs a paid instance type (Starter).

### One file on a machine you own

Any always-on machine with Docker (a small VM, a home server, a spare Mac). No clone, no `.env`:

```sh
curl -fsSL https://raw.githubusercontent.com/Vibiz-ai/principia/main/cloud/compose.yml -o compose.yml
docker compose up -d
docker compose logs principia | grep -A1 "Connect link"
```

The log prints `Connect link: http://127.0.0.1:8787/pair#K7QM-4XWD (10 min)`. That address only works on the machine
itself, so when the cloud runs on a server the log adds one line with the fix: a tunnel from your Mac
(`ssh -N -L 8787:127.0.0.1:8787 you@your-server`, then paste the link), or a public address (below). Need a new link?

```sh
docker compose exec principia principia-cloud pair
```

### Public HTTPS

ChatGPT and Claude.ai reach a Passport only over public HTTPS, and your phone is happier with it too. Point two domains
at the machine (for example `cloud.example.com` and `passport.example.com`), then turn on the `caddy` profile. Caddy
gets the certificates, and both public URLs follow from the domains:

```sh
PRINCIPIA_DOMAIN=cloud.example.com PASSPORT_DOMAIN=passport.example.com docker compose --profile caddy up -d
```

Tailscale or Cloudflare Tunnel work as well: set `PRINCIPIA_PUBLIC_URL` (and `OPEN_PASSPORT_PUBLIC_URL`) to the URL
your devices reach, then make a new connect link.

## Then, in Principia

1. **Cloud** → paste the connect link → **Connect**.
2. **Connect Claude** and **Sign in with ChatGPT** in the Accounts card. Each opens your browser once; nothing to copy.
3. **Run in the cloud…** on a company. The checklist sends the Passport, the workflows, the schedules that should fire
   in the cloud, the repo and only the keys and connections those workflows use. The company then shows **Ready**, or a
   short list of one-click fixes, and **Run once now** shows the first cloud run's result right there.

Your phone: **Workspace ▾ → Open on your phone** shows a QR code of a one-time sign-in link. The phone console has two
tabs, **Needs you** and **Runs**, plus the **Pause cloud** switch.

## What runs where

| Container | Does |
|---|---|
| `principia` | the control plane and the agent runtime (Node 24) with the pinned Claude Code, Codex and Gemini CLIs; serves the API, the phone console at `/console` and the connect page at `/pair` |
| `passport` | the unchanged Open Passport reference host. Each company you move gets a passport here, connected by default. (On Render it runs inside `principia`: `PRINCIPIA_PASSPORT=embedded`.) |
| `caddy` | only with `--profile caddy`: HTTPS for both domains |

Both images are published to GitHub's registry (`ghcr.io/vibiz-ai/principia-cloud`, `ghcr.io/vibiz-ai/open-passport-host`).
To build them from source instead: `docker compose -f cloud/compose.yml -f cloud/compose.build.yml up --build -d`.

### Your agents cannot read your keys

The control plane runs as root inside its container with six capabilities (`CHOWN`, `DAC_OVERRIDE`, `FOWNER`,
`SETUID`, `SETGID`, `KILL`) and nothing else, on a read-only root filesystem with `no-new-privileges`. Every agent
process (each step, its tools, git for your repos) starts as its own user, `agent` (uid 1001), with no capabilities.
That user cannot read `/secrets` (the master key and the passport admin token), `/data/control.db` (every encrypted
credential) or the runtime's databases; it owns only its run's home, the company folders and the run's artifacts.
`npm run cloud:isolation:smoke` checks it against a running cloud with a real shell step.

### What `up` creates

| Volume | Holds | Back it up |
|---|---|---|
| `principia-secrets` | `master.key` (wraps every stored secret) and `passport-admin`, generated once by the `init` service | **Separately** from `principia-data`. Whoever holds both can read your keys. |
| `passport-secrets` | a copy of `passport-admin`, the only secret the passport container sees | Not needed: `init` copies it again on every start. |
| `principia-data` | `control.db` (devices, companies, encrypted credentials, runs, asks, audit) and the runtime's run store | yes |
| `principia-workspace` | company folders and repo clones | optional (they can be cloned again) |
| `passport-data` | every passport revision, grants and the host's audit log | yes |

Ports bind to `127.0.0.1` only, unless you turn on the `caddy` profile.

## Accounts

- **Claude:** **Connect Claude** runs `claude setup-token` on your Mac and sends the token straight to the cloud (Pro,
  Max, Team or Enterprise; it lasts a year). Or paste a token, or an Anthropic API key.
- **Codex:** **Sign in with ChatGPT** makes a second ChatGPT sign-in just for the cloud. Runs that share it take turns,
  so a token refresh never signs you out. Or use an OpenAI API key.
- **Gemini:** Accounts ⋯ → **Add another provider**: a Gemini API key or a Vertex service account.
- When a real run finds a token expired or an account at its usage limit, the Accounts row and the company's readiness
  say so before the next 09:00 run, with the one fix.

## Configuration (all optional)

Every variable has a working default. Put overrides in a `.env` next to `compose.yml` (see [`.env.example`](.env.example))
or in your shell. Env vars always win over the generated files.

| Variable | Default | Meaning |
|---|---|---|
| `PRINCIPIA_PUBLIC_URL` | this machine; Render and Fly set it themselves | the origin your Mac and phone reach (links, cookies, OAuth callbacks) |
| `PRINCIPIA_DOMAIN`, `PASSPORT_DOMAIN` | unset | the two domains of the `caddy` profile; they set both public URLs |
| `PRINCIPIA_MASTER_KEY` | `/secrets/master.key` | 64 hex characters (or 32 bytes of base64); wraps every stored secret |
| `PRINCIPIA_SECRETS_DIR` | `/secrets` | where `init` writes the generated keys |
| `PRINCIPIA_WORKSPACE_NAME` | `Principia Cloud` | shown in the pane and console |
| `PRINCIPIA_LOG_RETENTION_DAYS` | `30` | run history and logs kept |
| `PRINCIPIA_CONNECTOR_ALLOW_PRIVATE` | unset | comma-separated hosts a connector may use even on private addresses |
| `PRINCIPIA_AGENT_UID` | `1001` | the user agents run as (`off` runs them as the control plane: not recommended) |
| `PRINCIPIA_PASSPORT` | unset | `embedded`: run the passport host inside this container on the cloud's origin |
| `OPEN_PASSPORT_PUBLIC_URL` | `https://$PASSPORT_DOMAIN`, else local | the passport origin other apps reach |
| `OPEN_PASSPORT_ADMIN_TOKEN` | `/secrets/passport-admin` | the passport host's admin token |
| `PRINCIPIA_VERSION`, `OPEN_PASSPORT_VERSION` | `latest` | image tags |
| `PRINCIPIA_ADMIN_TOKEN` | unset | 32+ characters: also allows `POST /v1/pair/start` with this bearer (scripts). The connect link from the log or `principia-cloud pair` is the normal way. |
| `PORT`, `HOST` | `8787`, `0.0.0.0` in the image | listen address inside the container |

**Pairing:** the connect link carries an 8-character code (single use, 10 minutes, stored hashed). Ten wrong tries from
one address in 10 minutes are refused for 10 minutes. The limit counts the socket address: behind a reverse proxy all
clients share one, so a bad actor there can block pairing for 10 minutes (it fails closed; run `principia-cloud pair`
again later). A paired Mac holds a device token that you can revoke from **Cloud → Workspace → Devices**.

## Not in v1

Webhooks, the GitHub App, server-side Codex device login, Forum routes and Codex access tokens answer `501 not_in_v1`.
Repos use a fine-grained personal access token (or none for public repos). See CLOUD.md §14.

## Development

```sh
npm run cloud:build                # out-cloud/control.mjs (plus the runtime bundles)
npm run cloud:console:build        # out-cloud/console (the phone console)
npm run cloud:test                 # node --test cloud/*.test.mjs, then vitest over src/cloud
npm run cloud:control:smoke        # boots control.mjs with a fake runtime and, if present, ../open-passport's host
OPEN_PASSPORT_SRC=../../open-passport docker compose -f cloud/compose.yml -f cloud/compose.build.yml up --build -d
node cloud/control.smoke.mjs --url http://127.0.0.1:8787 --link '<connect link>' --passport
node cloud/isolation.smoke.mjs --url http://127.0.0.1:8787 --link '<another connect link>'
```

Outside Docker, `PRINCIPIA_RUNTIME=fake node out-cloud/control.mjs` runs the control plane without agents.

`cloud/server.mjs`, `runner.mjs` and `telegram.mjs` are the earlier prompt-and-Telegram runner. They are kept so
existing installs keep working (`npm run cloud:start`, their variables are documented at the top of each file) and are
not developed further.
